# Bedrock

**A shared NixOS platform layer for interchangeable NixOS desktop profiles.**

Bedrock is the layer that sits between an existing NixOS installation and desktop profiles such as [Whitebox](https://github.com/amanogawa-subaru/whitebox) and [Blacknote](https://github.com/amanogawa-subaru/blacknote). It keeps machine-specific configuration and common system/user policy in one place while each profile supplies its own desktop environment, appearance, and profile-specific dependencies. The idea being that NixOS desktop profiles should be independent from machine-specific configurations, such as the ones generated by the NixOS installer. Bedrock composes the selected profile with the existing NixOS installation.

Bedrock is **not a standalone NixOS distribution or an installer for a blank disk**. Start with an, ideally, freshly-installed, bootable NixOS system.

## How it fits together

```text
Existing NixOS installation
  /etc/nixos/configuration.nix
             +
          Bedrock
  machine settings, shared modules,
  shared Home Manager policy, nixpkgs
             +
       Selected profile
             ↓
    /etc/nixos#<profile>
```

The generated `/etc/nixos/flake.nix` is a **composition portal**, not another configuration repository. Each output combines the existing host configuration, Bedrock, and **one** selected profile. Installing several profiles does not enable all of them simultaneously by design.

| Owner | Responsibility |
| --- | --- |
| Existing NixOS host | `/etc/nixos/configuration.nix`, hardware configuration, and the underlying installation |
| Bedrock | Canonical nixpkgs, detected machine settings, common NixOS modules and packages, shared Home Manager configuration, profile catalog, installer |
| Profile | Desktop/session, appearance, profile-specific modules and inputs |
| Generated portal | Compose the host, Bedrock, and selected profile; own no lockfile |

Bedrock's `flake.lock` pins the canonical nixpkgs revision. Profiles pin their own inputs, but their declared nixpkgs-consuming dependencies are wired to `bedrock/nixpkgs` by the portal. The portal itself intentionally has **no `/etc/nixos/flake.lock`**.

## Install

On an existing NixOS installation, run the following **as your normal user**, not root:

```bash
nix-shell -p git --run '
  git clone https://github.com/amanogawa-subaru/bedrock.git &&
  cd bedrock &&
  ./install.sh
'
```

The legacy `nix-shell` bootstrap supplies Git without requiring `nix-command` or flakes to be enabled beforehand. The installer enables the experimental features for its own early Nix commands and for the rebuild.

The installer:

1. Checks for an existing `/etc/nixos/configuration.nix`.
2. Detects graphics hardware, including supported NVIDIA/PRIME laptop configurations, and generates local `settings.nix`.
3. Creates local package and mount modules from examples **only when they do not already exist**.
4. Reads `profiles.nix`, lets you select a profile, and clones it into `~/nixos-profiles/<profile>/` if absent.
5. Discovers installed profiles and reads each profile's `bedrock-profile.nix` metadata.
6. Backs up conflicting, regular Firefox/LibreWolf `profiles.ini` files before Home Manager takes ownership; existing backups are not overwritten.
7. Generates `/etc/nixos/flake.nix`, runs a dry-build, then activates the selected profile.

An existing profile checkout is preserved rather than automatically pulled. The installer refuses to overwrite an existing `/etc/nixos/flake.nix` that it does not recognize as Bedrock-generated.

**Review the selected profile and local example modules before relying on the result.** In particular, your personal ignored files are not supplied by a fresh clone.

## Everyday use

Run `install.sh` and select a profile. If the profile does not exist in `~/nixos-profiles`, the installer will clone it from the repo. 
To switch to a different profile, run `install.sh` again and pick a different profile. 

If multiple profiles are already installed and represented in the generated portal, you can switch between them directly without rerunning `install.sh`.

Rebuild with your chosen installed profile:

```bash
sudo nixos-rebuild switch \
  --flake /etc/nixos#<profile> \
  --no-write-lock-file
```
When switching between desktop profiles, it is recommended to perform the rebuild from a TTY rather than from within the running desktop session. Home Manager may replace or remove profile-managed configuration files during activation, potentially disrupting the current session. Once activation completes, start the selected profile's compositor using UWSM:
```bash
uwsm start <compositor-name>.desktop
```
**Bedrock does not ship with a display manager by design.** It looks cool that way.

Always retain `--no-write-lock-file`! The generated portal is deliberately lockfile-free. Omitting `--no-write-lock-file` would generate a flake.lock which would need to be updated whenever you want to apply changes to Bedrock or any of the profiles (which is a total pain!). Bedrock's flake provides the canonical nixpkgs revision.

**Updating a Git checkout is separate from rebuilding.** The installer does not automatically fetch new Bedrock or profile commits. Update the desired repository yourself, then rebuild; rerun `./install.sh` when you need it to rediscover installed profiles or regenerate the portal.

## Local configuration

These files are machine/user-local and ignored by Git:

| File | Purpose | Installer behavior |
| --- | --- | --- |
| `settings.nix` | Username and detected graphics/PRIME settings | Regenerated on installer runs |
| `modules/user-packages.nix` | Personal system packages and NixOS program options | Created from example if missing; otherwise preserved |
| `modules/mount.nix` | Local filesystems and mounts | Created from example if missing; otherwise preserved |

Edit `modules/user-packages.nix` and `modules/mount.nix` for your machine. Do not assume changes to these ignored files will follow you to another computer.

Shared defaults live in `modules/` and `home/`. For example, Bedrock's Home Manager module configures shared browser policy, XDG defaults, and Neovim; profiles can provide their own appearance. Mutable browser data is distinct from the declaratively managed profile index.

## Profiles and dependency wiring

`profiles.nix` is the catalog of available profiles. Each installed profile is a separate checkout at `~/nixos-profiles/<id>/` and must provide:

- `flake.nix`, exporting `nixosModules.default`;
- `bedrock-profile.nix`, declaring `nixpkgsFollowers` as a list of input names.

For example, Whitebox declares:

```nix
{
  nixpkgsFollowers = [
    "home-manager"
    "catppuccin"
  ];
}
```

Blacknote declares `home-manager` and `stylix` instead. The installer uses these names to generate follows edges from each dependency's `nixpkgs` input to `bedrock/nixpkgs`; it does not assume all profiles use the same dependencies. The profile itself need not declare a dummy `nixpkgs` input.

The current portal generator targets **`x86_64-linux`** and expects the documented module outputs. Additional architectures and different profile interfaces are not implemented by this installer.

## Repository map

```text
bedrock/
├── flake.nix                 # Bedrock inputs and exported modules
├── flake.lock                # Canonical nixpkgs pin and Bedrock inputs
├── default.nix               # Shared NixOS module entry point
├── home/                     # Shared Home Manager configuration
├── modules/                  # Shared system policy and local module templates
├── profiles.nix              # Available profile catalog
├── install.sh                # Discovery, portal generation, validation, activation
└── settings.example.nix      # Machine-settings template
```
